最初に小さな機能をプロジェクトに追加しました。より大きな変更には、さらに堅牢なプロセスが必要です。GitHub Copilot app は組織の既存の開発フローに沿って動作するよう設計されており、適切なものを適切な方法で構築できます。このレッスンから複数のレッスンにわたり、一般的なエージェント主導の開発プロセスを実践します。Issue から新機能を作成し、コードが妥当で機能が期待どおりに動作することを確認してから、プロジェクトへのマージを進めます。

> [!NOTE]
> 機能のワークフローを進める間は、同じセッションを使います。通常は、扱うファイルの種類ごとに異なるセッションやプル リクエスト（PR）を使いますが、ここでは中心的な概念に集中するため手順を簡略化します。

このレッスンでは、次のことを行います。

- GitHub Issue から新しいエージェント セッションを開始する。
- **Plan** モードで要件を定義する。
- **Autopilot** モードで新機能を実装する。
- コードをレビューする。
- ブラウザー キャンバスで機能を手動検証する。

この機能の作業を続けながら、リポジトリの命令を更新し、既存の `quality-checks` skill をカスタマイズして、Model Context Protocol（MCP）による検証を追加し、品質保証（QA）エージェントを作成し、機能の PR を開きます。

## シナリオ

Tailspin Toys のカタログが大きくなり、訪問者がカテゴリーとパブリッシャーでゲームを絞り込める必要があります。バックログの Issue に機能は記載されていますが、カテゴリーの組み合わせ方など、実装前に合意が必要な詳細があります。Plan モードで決定事項を確認し、範囲を限定した実装を Autopilot に許可します。

## 背景

人工知能（AI）コーディング エージェントを開発フローに導入しても、基本は変わりません。むしろ、基本がさらに重要になります。多くの開発者は、次のような流れで作業します。

1. 必要な作業の詳細が記載された Issue を開く。
2. 作成するものの計画を立てる。
3. コードを作成してレビューする。
4. テストを実行してコードを検証する。
5. 新機能を手動で検証する。
6. プル リクエストを作成する。
7. コードのレビューと継続的インテグレーションのプロセスが成功したら、コードをマージする。

> [!NOTE]
> 正確な手順はチームや組織によって異なりますが、多くの場合は上記の流れに沿っています。

標準的なアプローチを守ることで、AI が生成したコードが要件を満たし、人間が作成したコードと同じ審査プロセスを通るようにできます。

## セッション モード

**セッション モード**は、エージェントの自律性を制御します。プロンプト フィールドの下にあるドロップダウンから設定でき、いつでも変更できます。

- **Interactive**: 開発者とエージェントが共同で作業します。エージェントは変更を提案し、続行前に開発者の入力を待ちます。
- **Plan**: エージェントが最初に計画を作成します。実行前に計画をレビューして承認します。
- **Autopilot**: エージェントが自律して作業し、入力を待たずにコードの作成、テストの実行、反復を行います。

Plan モードで開始して計画をレビューし、その後 Autopilot で実装します。

## Issue からセッションを開始する

セッションを開始する前に、星評価の PR がマージされ、ローカルの `main` が最新であることを確認します。

1. サイドバーの **Sessions** で Tailspin Toys のリポジトリ フォルダーを選択し、リポジトリの上部ナビゲーションで **Issues** を選びます。既存の Issue **Allow users to filter games by category and publisher** を開きます。テンプレートで用意された Issue を使うため、新しく作成する必要はありません。
2. **New session** を選択し、更新済みの `main` を基にした **new working tree** を選びます。

    ![GitHub Copilot app の Issue ビューで New session ボタンを矢印で示した画面](../../../_images/app-new-session-from-issue.png)

3. Issue がセッションに添付されていることを確認し、モード セレクターで **Plan** を選択します。

> [!NOTE]
> Node.js または npm が見つからない場合は、エージェントに `node --version` と `npm --version` を実行するよう依頼します。ターミナルでは動作するのにセッション内で見つからない場合は、アプリの PATH またはバージョン マネージャーの設定を確認し、アプリを完全に終了して再起動します。失敗した操作とチェックをもう一度行ってください。エージェントが npm を見つけられないという理由だけで、npm を再インストールしないでください。

## フィルター機能を計画する

計画を立てると、Copilot がコードを書く前にアプローチをレビューできます。Issue からセッションを始めたため、Copilot は機能の要求をコンテキストとしてすでに把握しています。次のプロンプトを送信します。

1. 次のプロンプトを Copilot に送信します。

    ```plaintext
    Build this feature.
    ```

2. Copilot の質問に答え、計画を Issue の受け入れ条件と照らし合わせます。カテゴリーとパブリッシャーによる絞り込み、アクセシブルなコントロール、データ アクセスの変更、テストが含まれていることを確認します。複数のカテゴリーをどう組み合わせるか、一致するゲームがない場合にどうなるかなど、不明確な動作について話し合います。
3. 計画に、プロジェクトの既存ツールを使う lint、単体テスト、エンドツーエンド（E2E）テスト、型チェックが含まれていることを確認します。計画はフィルター機能の実装とテストに絞り、品質ワークフローが完了するまで PR は作成しないようにします。必要な修正を計画に反映してから承認し、後で検証できるよう Issue の URL と合意した追加の取り決めを控えます。

## Autopilot を明示的に承認する

計画に納得したら、実装を承認してモードが切り替わったことを確認します。

1. **Approve and implement this plan**、または使用中のバージョンで表示される同等のオプションを選択します。
2. 承認によってモードが自動的に切り替わると決めつけず、モード表示が **Autopilot** になっていることを確認します。

Copilot は実装を開始し、計画に沿ってコードを作成し、テストを実行して反復します。

> [!NOTE]
> 承認後すぐに実装が始まることがあるため、先に計画をレビューしてください。依存関係の不足やポートの競合が報告された場合は、チェックを完了と見なす前にセットアップの問題を解決します。停止するのは自分で起動したサーバーだけにしてください。

## 実装をレビューして検証する

生成されたコードも、ほかのコードと同じように、マージ前にレビューします。フィルター機能を確認し、チェック結果を検証してください。

1. **Changes** を開き、フィルター機能の実装とテストを確認します。
2. 複数カテゴリーとパブリッシャーの組み合わせを含め、結果を Issue と承認済みの追加の取り決めに照らし合わせます。変更が既存のリポジトリの命令に従っていることも確認します。
3. lint、単体テスト、E2E テスト、型チェックの結果を確認します。スキップされたチェックは成功ではありません。
4. 実装を受け入れる前に失敗を解消し、該当するチェックを再実行します。Playwright の E2E 設定はサイトをビルドしてプレビューを配信し、ローカル サーバーを再利用する場合があります。テスト対象が以前のレッスンのサーバーではなく、この worktree のサーバーであることを確認します。

## 新機能を確認する

ブラウザーで機能を操作し、Issue と計画に沿った結果になることを確認します。

1. 次のプロンプトを Copilot に送信して、アプリを起動し、ブラウザー キャンバスでページを開きます。

    ```plaintext
    Start the app and open it in the browser canvas.
    ```

2. アプリが起動し、Copilot app 内にブラウザー ウィンドウが開くのを待ちます。
3. カテゴリーを選択し、結果がそのカテゴリーと一致することを確認します。フィルターを解除してからパブリッシャーを選択し、結果がそのパブリッシャーと一致することを確認します。
4. カテゴリーとパブリッシャーのフィルターを組み合わせ、Issue と承認済みの計画に照らして結果を確認します。複数カテゴリーがサポートされる場合は、合意した組み合わせの動作も検証します。
5. 該当するゲームがない組み合わせを試し、空の状態を確認します。フィルターを解除またはリセットし、全ゲームの一覧に戻ることを確認します。
6. 確認が終わったら、次のプロンプトを Copilot に送信して、このセッションで起動した開発サーバーを停止します。

    ```plaintext
    Stop the dev server and close the browser canvas.
    ```

## 次のレッスンに向けてセッションを保持する

フィルター機能の PR はまだ作成、マージしません。次のレッスンでも同じ作業環境を続けて使います。

1. 次のレッスンのために、このセッション、worktree、ブランチを保持します。
2. 開発サーバーを停止した後は、セッションをアイドル状態にしてかまいません。次のレッスンで同じセッションに戻ります。

- **Plan** モードで要件を定義しました。
- **Autopilot** モードで新機能を実装しました。
- コードをレビューしました。
- ブラウザー キャンバスで機能を手動検証しました。

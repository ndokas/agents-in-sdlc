フィルター機能の実装、命令の更新、skill の更新、品質保証（QA）プロファイル、テストを1つのブランチに保存しました。これらをまとめてレビューし、PR を開きます。星評価の PR は自分でマージしましたが、今回は **Agent Merge** にプロセスの管理を任せます。

> [!NOTE]
> 通常は、機能、命令、skill の更新、QA エージェントを複数の PR に分けます。ワークショップを簡潔にするため、フィルター機能と品質ワークフロー全体を1つのセッションとブランチにまとめ、この PR に含めます。

このレッスンでは、次のことを行います。

- Agent Merge の概要と、マージのライフサイクルを自動化する仕組みを確認する。
- 機能の PR 全体と検証の証拠を確認する。
- レビュー後に Agent Merge を許可し、PR がマージされたことを確認する。

## シナリオ

フィルター機能のワークフローを通じて、Copilot を使って機能を計画、実装、検証しました。Tailspin Toys は、マージの承認を開発者の管理下に置いたまま、残りの PR 作業を自動化したいと考えています。

## Agent Merge の概要

**Agent Merge** は、GitHub Copilot app で PR をマージするために必要な残りの作業を自動化します。有効にすると、アプリのセッションが PR を読み取り、失敗した継続的インテグレーション（CI）チェックの修正、レビュー コメントへの対応、必要に応じたリベースなど、マージを妨げる問題に対処します。GitHub でマージが許可されると PR をマージします。バックグラウンドで動作し、アプリを再起動しても継続し、PR がマージされると自動的に無効になります。

ここまでは、自分で **Merge pull request** を選択していました。Agent Merge に任せることもできますが、コードの編集とマージには明示的な許可が必要です。マージを許可する前に、エージェントが実行できる操作と作業内容を確認してください。

## Agent Merge で PR を管理する

コードの作成とレビューが終わったら、Agent Merge に PR の作業を任せます。メニュー項目を選ぶだけでは開始されないため、ボタンを押してプロセスを開始してください。

1. エージェント ピッカーで **Default agent** を選択します。
2. **Create PR** の横にあるドロップダウンを選択します。
3. **Agent Merge** を選択します。ボタンの表示が **Agent Merge** に変わります。
4. **Agent Merge** ボタンを選択してプロセスを開始します。

Agent Merge が開始されると、次の作業を行います。

- タイトルと説明を付けて PR を作成します。
- Issue からセッションを開始した場合は、説明の本文で関連する Issue に言及します。
- ターゲット ブランチに対するリベースを行うか、マージ競合に対処します。
- CI プロセスを監視し、すべてのチェックが成功するよう対応します。
- 他の開発者や Copilot code review からのフィードバックについて PR を監視し、コメントを解決するために更新します。
- すべての条件が満たされた後、必要に応じて PR を自動マージします。

マージを許可する前に、PR の差分と検証の証拠をレビューします。

5. PR の差分と検証結果を確認します。
6. **Agent Merge** の横にあるドロップダウンを選択します。
7. **Merge pull request** の横にチェックが付いていることを確認します。
8. 次のように明示的に指示して、エージェントにマージを依頼します。

    ```plaintext
    Merge the PR once all required checks and approvals pass. Do not bypass repository protections.
    ```

9. エージェントの進行状況を確認し、報告された阻害要因を解決します。続行する前に PR の状態が **Merged** であることを確認してください。マージ権限が有効になっていることやエージェントが動作中であることは、マージ完了の確認にはなりません。

> [!IMPORTANT]
> Agent Merge はリポジトリの保護や権限不足を回避しません。続行する前に、それらの阻害要因を解決してください。

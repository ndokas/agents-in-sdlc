GitHub Copilot を agent mode で使うと、コードベースを調べ、変更を提案し、ファイルを編集してコマンドを実行します。VS Code の Copilot Chat では、ツールの呼び出しとファイル編集をリアルタイムで確認できます。差分をインラインでレビューし、個々の変更を採用または取り消し、エディターを離れずに追加のプロンプトを送って作業を調整できます。

この演習では、次のことを行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視する。
- 提案されたファイル編集をレビューして採用する。
- セッションの途中でエージェントに指示し、高コントラスト モードに加えてライト モードの切り替えを追加する。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ用カスタム エージェントは、高コントラスト モードを実装しています。作業の途中でデザイン チームから追加依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライト モードの切り替えも追加します。新しい会話を始めるのではなく、既存のセッションを誘導して作業を拡張します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが調べたファイル、実行したコマンド、提案した編集など、各手順が表示されます。ファイルの編集は、差分と **Keep** / **Undo** 操作とともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントが作業している間、チャットをスクロールして各ツールの操作を確認します。ファイルの読み取りや編集、実行を依頼されたターミナル コマンドが表示されます。
3. エージェントがファイル編集を提案すると、差分がインラインで表示されます。
   - **Keep** を選択すると変更を採用します。
   - **Undo** を選択すると変更を取り消し、エージェントに再度作業させます。
4. チャット上部の **Files changed** を開くと、セッションでエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ターミナル コマンドの実行などに許可が必要な場合、エージェントは一時停止し **Allow** の確認を表示します。内容を確認し、許可できるコマンドだけを承認してください。

5. エージェントが高コントラスト モードの実装を終えるまで待ちます。最後に、変更内容をまとめたメッセージが表示されます。

## エージェントにライト モードを追加するよう指示する

高コントラスト モードができたので、同じ会話を続けてライト モードの切り替えを追加します。同じチャット セッションを使うため、エージェントは先ほど編集したコンポーネント、スタイルの方針、local storage を使う実装パターンを把握しています。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントが既存の変更を確認し、ライト モードの追加を提案することを確認します。
3. 新しい編集を確認し、それぞれ **Keep** または **Undo** を選択します。
4. エージェントが意図と異なる方向に進む場合（たとえば切り替えのユーザー インターフェイス（UI）を望まない方法でリファクタリングする場合）は、チャット入力欄の隣にある **Stop** ボタンで停止し、明確な追加メッセージを送ります。

> [!TIP]
> 進行中のセッションを誘導すると、最初からやり直すより効率的です。追加プロンプトで「Cascading Style Sheets（CSS）を簡潔にし、セレクターの重複ではなく CSS 変数を使う」のように調整したり、「3 つ目の切り替えを追加せず、既存の設定パネルにライト モードを統合する」のように方向を修正したり、「両方の切り替えにキーボード ショートカットを追加する」のように範囲を広げたりできます。

## 作業ファイルをレビューする

変更を commit する前に、エージェントが編集した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されています。
3. 変更されたファイルをいくつか開いて差分を確認します。Accessible Rich Internet Applications（ARIA）属性、キーボード ナビゲーション、セマンティック HyperText Markup Language（HTML）、local storage による設定の保持など、カスタム エージェントが示したアクセシビリティ パターンが反映されていることを確認します。
4. 問題がなければ **Source Control** パネルから変更を stage して commit します。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat の agent mode を使って、実行中のセッションを監視、誘導しました。ファイル編集を確認し、変更を採用または取り消し、コンテキストを失わずに追加プロンプトを送って作業を拡張しました。

このレッスンでは、次のことを行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を採用または取り消しました。
- 追加プロンプトを使ってセッションの途中で作業を誘導しました。

[次のレッスン][next-lesson]では、アクセシビリティ機能のプル リクエスト（PR）を公開し、このラボでローカルのカスタム エージェントが作成した変更をレビューします。
